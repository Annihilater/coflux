# Coflux 2.11.0

**A desktop-only release: the built-in browser keeps one login per project instead of one per worktree.**

Nothing in the center or the runtime changes. Install the desktop app; daemons on other machines need no action.

## Highlights

- **Browser state is shared across a project's worktrees.** Cookies, site storage, the HTTP cache, trusted certificates and site permissions of the built-in browser now belong to the project: sign in to a site in one worktree and every other worktree of the same project is signed in too. The device view keeps its own separate state per device. Different projects, and a project and its device view, stay isolated from each other. Tabs are still per workspace, history is still shared across the app, and annotations still belong to their workspace.
- **Clearing follows the new scope.** Clearing cookies, the cache or trusted certificates from a browser tab applies to the whole project (or device view) that tab belongs to, so it signs out every worktree of that project.
- **Remote projects work as before.** In a remote project, `localhost` still reaches the project's device.

## Install or update

**Mac:** install `coflux-2.11.0-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:** this release contains no runtime changes, so there is nothing to update. The packages are published at the same version for consistency:

```sh
npm install -g cofluxd@2.11.0
cofluxd update
```

## Upgrade impact

- **Existing built-in browser data is deleted.** Browser state was kept per workspace until now; it is not merged into the new per-project state but removed when the app starts. After updating, sign in once per project (and once per device view) in the built-in browser. Browsing history is kept.
- Because cookies ignore ports, two worktrees of one project running dev servers on different `localhost` ports now share same-named `localhost` cookies.
- No schema migration, no server configuration, and no daemon capability is involved. A machine running 2.10.0 daemons works unchanged with the 2.11.0 desktop app.
