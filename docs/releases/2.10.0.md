# Coflux 2.10.0

**Annotate a page in the built-in browser and hand it to your agent, a changes view that opens instantly as a file tree, notifications that land on their terminal, and terminals that survive runtime updates from now on.**

This release touches every layer: the desktop app, the runtime (a new `coflux-ptyd` process), the `coflux` CLI and the center. Read **Upgrade impact** before updating headless machines.

## Highlights

- **Browser annotations.** In a browser tab, turn on annotate mode from the toolbar, click any element and write what should change; attach a reference image or rely on the automatic screenshot of the element. Numbered pins mark annotated elements on the page, and a side panel lists every annotation of the workspace grouped by page. Agents pick them up with `coflux annotations list`, including the component chain and source location when the page exposes them (React and Vue development builds), the element's selector and styles, and the image paths; `coflux annotations watch` waits for new ones hands-free. When the agent runs `coflux annotations resolve <id> --note "..."`, the pin turns into a check and the note appears in the panel, where you confirm it or reopen it with a follow-up. The panel's hand-off menu types a short instruction into any of the workspace's agent terminals without taking focus. Annotations belong to the workspace, live on the device that hosts it, and survive restarts; their content travels end to end between the desktop and that device and never reaches the center, which only relays counts.
- **Terminals survive runtime updates.** A new long-lived `coflux-ptyd` process now owns the terminals. Updating the runtime replaces the supervisor while shells, running programs, screens and scrollback stay in place; output produced during the brief pause is kept. Updating no longer asks for confirmation unless `coflux-ptyd` itself changes, which is offered as its own action and says plainly that terminals will end. A supervisor crash now recovers on its own.
- **The changes view is a file tree beside a single-file diff.** Opening the changes view fetches only the list of changed files in one round trip and shows it as a compact tree with per-file additions, deletions and status. Only the selected file's diff is loaded, side by side or inline, with unchanged stretches collapsed until you expand them. The arrow keys move through the tree, and the view remembers the last file per workspace.
- **Clicking a notification lands on its terminal.** Clicking a desktop notification, either as a banner or later from Notification Center, brings Coflux forward on the right workspace, activates the terminal that raised it and gives it keyboard focus. This works for agent notifications and for approval or question alerts.
- **The built-in browser has no bookmarks.** The star button, the bookmarks bar and bookmark suggestions are gone; the address bar suggests visited pages only. Browsing history, recent visits on a new tab and clearing history work as before. Existing bookmarks are dropped.
- **Plainer agent input card.** The card an agent raises to request a value now reads as an input request, attributes the agent's reason to the agent, and states which device receives the value and when the request expires.

## Install or update

**Mac:** install `coflux-2.10.0-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:** update `cofluxd` first, then the runtime:

```sh
npm install -g cofluxd@2.10.0
cofluxd update
cofluxd restart
```

**Agents:** the Claude Code plugin's coflux skill documents `coflux annotations`; update the plugin to 0.18.0.

## Upgrade impact

- **This update ends local terminals one last time.** The supervisor running today predates `coflux-ptyd` and cannot hand its terminals over, so the update that introduces it still closes them. Every later update that only changes the supervisor keeps them.
- **Machines installed with an older npm `cofluxd` have no terminals until `cofluxd` is updated.** The new supervisor refuses to start without `coflux-ptyd` and says so; `npm install -g cofluxd@2.10.0`, `cofluxd update` and `cofluxd restart` install and start both services. The desktop app manages this by itself.
- **Browser annotations need the 2.10.0 runtime on the workspace's device.** A device running an older runtime shows a notice that it needs updating instead of the annotation panel. Pin counts refresh live across desktops once the center runs 2.10.0; without it, annotations still load and save.
- **The changes view needs the 2.10.0 runtime** on the workspace's device and otherwise asks for an update.
- No schema migration and no server configuration change.
