# Coflux 2.20.2

**An executor write run now lists every file that changed in its workspace, and a refused run tells the agent to wait instead of rewriting its prompt.**

A coding agent hands the executor a bounded job with `coflux executor run --write`, and the command ends by printing the files the run changed, the list the agent reviews before committing. Until this release that list held only the files the executor edited with its file tools. Anything its shell commands wrote was missing: a file created with a redirect, a `sed -i` rewrite, a formatter's or a code generator's output. The 2.20.0 notes suggested checking `git status` instead, which does not exist in a folder that is not a git repository and, in one that is, mixes the run's changes with uncommitted work from before it.

In 2.20.2:

- The list is the workspace's net change over the run, whatever made it, shell commands included. Files the run deleted are listed too.
- In a git workspace, files git ignores (build output, dependencies) are left out unless the executor wrote one with its file tools, and a file that already had uncommitted changes before the run is listed only if the run changed it again.
- In a folder that is not a git repository, every file is compared by size and modification time.
- The list cannot tell who made a change: anything else writing to the workspace during the run, such as the user or another agent, shows up too.
- When the workspace cannot be scanned completely, for example a very large folder outside git or a run stopped with little time left, the output says the list is incomplete rather than quietly listing less.
- A second write run in a workspace that already has one is refused with a reason in English that names the run holding the workspace. The next step now says to send the run again once that run finishes; it no longer tells the agent to adjust its prompt.
- Every other way a run can end gets its own next step: a model failure points at the executor settings, a stopped run asks why it was stopped before sending it again, and a run whose host went away asks for a look at the workspace first.
- The Claude Code plugin moves to 0.24.0 with the updated `coflux` skill.

## Install or update

**Mac:** install `coflux-2.20.2-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.20.2
cofluxd update
```

## Upgrade impact

- The executor runs on the Mac that hosts it. Where Coflux.app hosts it, update the desktop app, which also carries the `coflux` command line tool. Where an npm-installed `cofluxd` hosts it, install `cofluxd@2.20.2` and run `cofluxd update`.
- The executor exists only on macOS, so Linux hosts gain nothing from this release and need no action.
- Changes inside git submodules are not listed.
- Agents need no change: `coflux executor run` takes the same arguments.
- No center, protocol or configuration change.
