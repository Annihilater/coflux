# Coflux 2.16.1

**Headless x86_64 hosts without systemd can run Coflux again.**

In 2.16.0, `cofluxd up` and `cofluxd restart` refused to start the service on x86_64 Linux hosts without systemd, such as containers, and `cofluxd run` refused on every x86_64 host, with "The installed Coflux is too old to run without systemd." even after `cofluxd update`. `cofluxd` recognises a launcher that can supervise itself by a marker inside the launcher binary, and the x86_64 builds of 2.16.0 did not contain it. arm64 hosts were not affected, and x86_64 hosts using systemd or launchd kept working through `cofluxd up`.

## Install or update

**Mac:** install `coflux-2.16.1-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.16.1
cofluxd update
cofluxd restart
```

## Upgrade impact

- Affected hosts: run the three commands above; `cofluxd restart` then starts the self-managed service. Terminals are kept.
- Every release now checks each launcher build for the marker before publishing.
- No center, protocol or configuration change.
