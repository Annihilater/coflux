# Coflux 2.16.0

**Every device now runs one replaceable runtime behind a small launcher, so terminal and session logic updates itself without a restart; the changes view becomes a whole-workspace file explorer; and headless Linux hosts no longer need systemd.**

Deploy the center before this release reaches devices. The desktop migrates on its own the first time the new app starts, with terminals kept. Headless hosts need one manual update, described under Upgrade impact.

## Highlights

- **One runtime, updated in place.** A device now runs three processes: `coflux-ptyd`, which owns the terminals, a minimal `coflux-launcher`, and `coflux-runtime`, which holds everything else, including the terminal and session logic that used to live in the supervisor. Runtime updates, whether pushed by the center or bundled with a new desktop app, now arrive automatically: the launcher starts the new runtime, checks that it took over every live terminal and connected, and rolls back to the previous version if it does not. Terminals stay open throughout; only a change to `coflux-ptyd` itself still needs a confirmed restart.
- **The desktop's runtime follows the app.** After an app update the local runtime switches to the bundled version with no click. If the new runtime fails its checks, the runtime panel says the update could not be applied and offers to retry.
- **A whole-workspace Files view.** The Changes button is now Files. It lists every file in the workspace, not only the changed ones, with change decorations on files and folders, dimmed ignored folders and struck-through deletions. A Changed only toggle brings back the old list and is remembered across restarts; Command-F filters by path, and a switch in the header moves between the diff and the file. Folders on very large or non-repository workspaces load lazily.
- **Command-click lands in the Files view.** Command-clicking a path in a terminal now reveals the file in the Files view at the referenced line, expanding folded diff context when needed. The read-only file tab is still available from the right-click menu as Open in Tab.
- **Headless Linux hosts without systemd.** On containers, WSL and distributions without systemd, `cofluxd up` now runs the service itself, supervised by the launcher's watch mode. `cofluxd run` is a foreground entry point for containers; run them with `docker run --init`.
- **English command-line output.** `cofluxd` and `coflux` now print English product copy, with colour that respects `NO_COLOR`.

## Install or update

**Mac:** install `coflux-2.16.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.16.0
cofluxd update
cofluxd restart
```

## Upgrade impact

- **Headless hosts must update once by hand.** Run `npm i -g cofluxd@latest && cofluxd update && cofluxd restart` on every headless device. Terminals are kept. Until then the device keeps working on its current version but receives no further automatic updates, and an older `cofluxd update` refuses this release. After this one step, runtime updates arrive automatically again.
- **The desktop migrates by itself.** The first start of the 2.16.0 app replaces the running supervisor with the launcher and runtime, keeping terminals open.
- **Each runtime update causes a brief pause.** Terminal and session logic is now part of the runtime, so every runtime update, including those pushed by the center, briefly pauses terminal output. Terminal holders and the de-duplication record for create and stop requests reset on each update.
- **Command-click on a terminal path opens the Files view** instead of a file tab; use the right-click menu to open a tab. The Changes button is renamed Files.
- **On systemd hosts, `cofluxd up` now fails loudly** when `systemctl --user` does not work. It used to report success.
- **Update the runtime before relying on the Files view.** Against a 2.15.0 or older runtime the desktop shows only the changed files, with a hint that the device is out of date.
- **Deploy the center first.** It must understand the new release manifest before this version becomes the latest release; against an older center, launcher devices receive no runtime updates. No migration and no server configuration change.
- The Claude Code plugin moves to 0.22.0 and ships with the release.
