# Coflux 2.19.0

**Remote screen now works: see and drive another of your Macs from the desktop app.**

The screen view shipped in 2.12.0 never actually connected. The desktop app silently discarded every message it sent to the other Mac, so the view sat on "preparing the virtual display" and then failed with "the remote device did not respond". 2.19.0 fixes that and the problems behind it on the remote side, and reshapes the screen into something you can find again.

In 2.19.0:

- **A screen belongs to a device, not to a workspace.** Open it with the new screen button at the top right of any workspace on that device, from the device's context menu in the sidebar, or from the command palette. Each device has at most one screen: opening it again from another workspace jumps to the same one.
- **Open screens are listed in the sidebar**, under their device. Click the row to switch to the screen; hover it and press × to disconnect, which ends the session and removes the virtual display on the other Mac. Switching to a workspace pauses the screen without disconnecting.
- **Choose the remote resolution** from the screen's status bar: follow the window (the default), or one of 1280×800, 1440×900, 1512×982, 1728×1117 and 1920×1080, always HiDPI. A fixed size stays put when you resize the window; the choice is remembered per device.
- The virtual display on the other Mac now comes up at the requested size, also when that Mac's displays were asleep or its lid closed.
- When something goes wrong, the desktop app and the remote helper now say where in their logs, instead of failing silently.

## Install or update

**Mac:** install `coflux-2.19.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.19.0
cofluxd update
```

## Upgrade impact

- **Both Macs need the 2.19.0 desktop app.** The fix for sending lives in the Mac you control from; the fix for the virtual display lives in the screen helper that ships only inside the desktop app, on the Mac being controlled. The updated app switches its local runtime to the bundled one by itself, which starts the new helper; terminals keep running.
- The controlled Mac must grant Coflux Screen Recording, and Accessibility for keyboard and mouse control; without Accessibility the picture is view-only.
- Screen tabs opened in earlier versions are dropped; open the screen again from the button or the sidebar.
- Headless (`cofluxd`) machines and Linux devices still cannot be controlled. No server change, no schema migration and no new configuration.
