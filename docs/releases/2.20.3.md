# Coflux 2.20.3

**A new terminal running fish no longer stalls for ten seconds or prints "could not read response to Primary Device Attribute query".**

fish 4.1 and later ask the terminal to identify itself as they start, and wait up to ten seconds for the answer. In Coflux the shell starts before the window connects to it, so the question went unanswered: every new fish terminal paused, printed the warning, and switched off some optional features. Other programs that ask the same question had the same problem in a terminal an agent started with no window, or in a tab that was open but not showing.

In 2.20.3:

- When no Coflux window is receiving a terminal's output (the terminal has just started, an agent drives it with nobody watching, or a window is reconnecting), the Coflux service on that device answers the question itself, with the same reply the desktop terminal gives. A program sees the same terminal whoever answers.
- When a window is receiving the output, the desktop terminal answers, as before, so its replies to a program's other questions (colours, keyboard protocol) still arrive in the order the program expects.
- A window that reconnects after the service already answered gets a fresh screen instead of a replay, so the same question is never answered twice.
- A terminal tab that is open but not showing now answers the program's questions too.
- Only this one question is answered on a window's behalf. Others still need a connected window, and a program that gets no answer treats the feature as unsupported, as it would in any terminal that lacks it.

## Install or update

**Mac:** install `coflux-2.20.3-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.20.3
cofluxd update
```

## Upgrade impact

- On a Mac, update the desktop app: it carries both the terminal service and the hidden-tab fix.
- A headless host that already runs the launcher receives the new terminal service automatically. Terminals stay open across the switch, with a brief pause. `cofluxd update` does it immediately.
- A terminal opened before the update already missed its startup question; the fix applies to terminals opened afterwards and to questions asked later.
- If you turned off fish's terminal query with `set -Ua fish_features no-query-term`, you can remove `no-query-term` from `fish_features` once every device you use is updated (`set -Ue fish_features` when it is the only entry).
- No center, protocol or configuration change.
