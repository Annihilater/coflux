# Coflux 2.15.0

**Agent launch settings follow your account, removals take effect the moment you confirm, and runtime restarts no longer roll back a healthy update.**

The center must be updated before desktops use the new account-level agent settings. Update the desktop app to get the other fixes; the runtime fix lands the next time the desktop restarts its runtime.

## Highlights

- **Agent settings belong to your account.** The agents you turn on in Settings > Agents and their launch commands are stored once per account on the center, so every Mac signed in to the account offers the same Agent submenu under Command-T, and a change on one Mac shows up on the others right away. Offline, the last received configuration keeps working and Settings > Agents is read-only.
- **Removing a workspace, project or terminal is instant.** The item disappears as soon as you confirm instead of waiting for the device to finish deleting the worktree. If the removal fails, the item comes back. Removing the workspace you are in switches to the project's main workspace.
- **Restarting the runtime no longer rolls back a good update.** A runtime with many open terminals can take a few seconds to restore them; the desktop now waits for it instead of declaring the update failed, and a new runtime no longer exits when the old one is still releasing its lock.
- **Command-T always highlights the first item.** The new-tab menu's first entry is highlighted whenever the menu opens from the keyboard shortcut, even after you last used the mouse.

## Install or update

**Mac:** install `coflux-2.15.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.15.0
cofluxd update
```

## Upgrade impact

- **Turn your agents on once more.** Agent settings moved from each Mac to your account; the values saved by 2.14.0 are not carried over. After updating, open Settings > Agents, turn on your agents and enter their launch commands again.
- **Update the center before the desktop.** Against an older center, Settings > Agents is read-only and the Command-T menu has no Agent entry. A 2.14.0 desktop ignores the account settings and keeps its local ones until it is updated.
- **The runtime fix needs a runtime restart.** It lives in the supervisor, which a hot upgrade does not replace; use the desktop's restart-runtime action after updating.
- Schema migration 9 adds the `account_agent_settings` table. It only adds a table, so rolling the server back is safe.
- No daemon, CLI or server configuration change.
