# Coflux 2.20.0

**The executor can finally run commands, and it can batch its work into one script.**

The executor is the small agent built into Coflux that a coding agent hands a bounded sub-task to with `coflux executor run`. Until this release it could read, search and edit files but could not run a single command: its sandboxed shell was never registered with the agent engine underneath it, so jobs such as chasing a failing test suite were out of its reach.

In 2.20.0:

- The executor runs shell commands: tests, builds, `git status`, `git diff`. Every command runs inside the macOS kernel sandbox, which lets it write only the workspace it was started in (nothing at all in a read-only run), gives it no network, and keeps it away from local services.
- The executor can write one script that calls its tools, instead of spending a model round trip on each call: run the test suite and keep only the failures, or read or edit many files in one step. Every call a script makes passes the same sandbox and path checks as a direct call. On the run card a script step is one row named after its first line, followed by the calls it made.
- The executor runs on version 1.3.0 of its agent engine, pi: the executor settings list newer models, and custom OpenAI-compatible endpoints get the engine's latest streaming fixes.
- The executor's engine no longer adds its attribution headers to requests sent to OpenRouter, NVIDIA NIM or Cloudflare.

The list of changed files an executor run reports covers the files it edited with its file tools; a file created by a shell command is not listed, so check `git status` after a run.

## Install or update

**Mac:** install `coflux-2.20.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.20.0
cofluxd update
```

## Upgrade impact

- The executor runs on the Mac that hosts it. Where Coflux.app hosts it, update the desktop app. Where an npm-installed `cofluxd` hosts it, install `cofluxd@2.20.0`, which brings the new engine.
- The executor exists only on macOS, so Linux hosts gain nothing from this release and need no action.
- Agents need no change: `coflux executor run` takes the same arguments, and the executor settings carry over.
- No center, protocol or configuration change.
